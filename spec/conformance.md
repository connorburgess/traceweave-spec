# Conformance levels

Version: 0.1.0-draft.1. Levels 1 and 2 have local validation tooling, and level 4 has vector checkers (see below).

1. **Record structure:** validate the draft predicate and restricted statement schemas, reject unknown fields, and preserve exact referenced bytes. Passing a schema does not validate external claims or algorithm support.
2. **Commitment opening:** recompute the specified exact-byte commitment with its private nonce. This proves correspondence to that opening, not authenticity or chronology.
3. **Attestation verification (planned):** verify a real envelope under an explicit trust policy, reporting identity and independent time results separately.
4. **Profile reproduction:** independently reproduce the extraction and matching vectors for a supported profile. The vectors are [test-vectors/extraction](../test-vectors/extraction/README.md) (`go-tokens`, `rust2024-tokens`), [test-vectors/extraction-typescript](../test-vectors/extraction-typescript/README.md) (`ts-tokens`; `tsx-tokens` is a deferred draft and not required), [test-vectors/extraction-text](../test-vectors/extraction-text/README.md) (`text-plain`; `text-markdown` is a draft and not required) and [test-vectors/matching](../test-vectors/matching/README.md), under the [extraction](extraction.md) and [catalogue and report](catalogue-report.md) contracts and the [TypeScript](../profiles/typescript.md) and [text](../profiles/text.md) profiles. The repository includes a checker for each vector set; a checker validates recorded outputs and is not an extractor, so level 4 is claimed by an implementation that reproduces the vectors, not by this repository.
5. **Detection evaluation (planned):** report a measured failure envelope and false-alarm unit for the full search pipeline.

The repository checks levels 1–2 for synthetic fixtures and DSSE framing only. It has no complete DSSE signer/verifier, token extractor, resolver, or benchmark corpus; the vector checkers validate recorded outputs: the extraction and matching checkers validate recorded token streams, fingerprints and reports without lexing; the TypeScript and text checkers also re-lex every input with reference lexers written from the profile; none is a production extractor, matcher or verifier. Claiming conformance MUST name the draft version, level, profile versions, and tested implementation.

Stable profiles require two implementations that agree on positive and negative vectors. Experimental profile documents are not approved algorithm registrations. CLI names and agent workflows are optional implementation interfaces, not core conformance requirements.
