# WEB.6 proposal — source-validation ledger

Checked 2026-11-27 for the [PROPOSED amendment](web6-budget-amendment-proposal.md). Primary pages were read directly; the supplied research was a starting point, not accepted authority. No external quotation is reproduced here; summaries distinguish normative requirements, informative guidance and local engineering choices. This ledger validates source support and bounds, not implemented compliance. URL contents can change; the future protocol must pin applicable source versions where necessary.

## Primary documentation checked

| ID | Primary source | Validated support and correction / limit |
| --- | --- | --- |
| L1 | [web.dev INP](https://web.dev/articles/inp) (page reports update 2025-09-02) | Field good threshold ≤200 ms at p75 of visits, mobile/desktop segmentation. A lab≤200 ms control target is an engineering choice; neither WCAG mandate nor field INP proof. INP is not whole-job duration |
| L2 | [web.dev LCP](https://web.dev/articles/lcp) (update 2025-09-04) | Visible-content load metric; good guidance ≤2.5 s at p75. Does not establish time-to-interactive; proposed shell-ready mark is a separate definition |
| L3 | [web.dev long tasks](https://web.dev/articles/optimize-long-tasks) (update 2024-12-19) | Tasks>50 ms are long; yielding/offloading guidance. Does not impose a universal zero-long-task compliance standard or bound total compilation time |
| L4 | [web.dev JS startup optimization](https://web.dev/articles/optimizing-content-efficiency-javascript-startup-optimization) | Less critical JS, code splitting and lazy loading can reduce startup costs; no Traceweave 150,000 B or 1,200,000 B ceiling is supplied |
| L5 | [web.dev Brotli codelab](https://web.dev/articles/codelab-text-compression-brotli) | Brotli/gzip guidance and measurement; old hosted demo warning is present. No compression ratio inferred and no demo executed. Candidate Brotli preferred/gzip fallback must be verified by actual encoded bytes/headers, not by “MB” labels |
| L6 | [MDN instantiateStreaming](https://developer.mozilla.org/en-US/docs/WebAssembly/Reference/JavaScript_interface/instantiateStreaming_static) | Streamed compile/instantiate path; correct application/wasm MIME, CSP/environment constraints. Not streaming of user files through tokenizer, not a no-blocking guarantee; current loader instead compiles a full response buffer |
| L7 | [WCAG2.2 Recommendation](https://www.w3.org/TR/2024/REC-WCAG22-20241212/) and informative [keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html), [focus visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [errors](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html), [status](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) explanations | Normative criteria include keyboard operation 2.1.1, no keyboard trap 2.1.2, focus visible 2.4.7, textual error identification 3.3.1 and programmatic status 4.1.3. Understanding pages are informative. Selected tests do not establish whole WCAG conformance or numerical speed budgets |
| L8 | [web.dev off-main-thread guidance](https://web.dev/articles/off-main-thread) | Worker architecture can reduce main-thread contention; proposed worker requirement is a project design choice, not a fact mandated by WASM, WCAG or the existing WEB.6 text |
| L9 | [MDN Worker.terminate](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate) | Host can stop worker without waiting for its code to finish. The 1,000 ms project deadline needs real tests; no unbounded next-chunk escape. It supplies no erasure guarantee |
| L10 | [MDN transferable objects](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Transferable_objects) | ArrayBuffer ownership transfer detaches sender's buffer; transfer does not eliminate WASM linear-memory copies, stringify/parser allocations or the need to cap input. No 25 MB whole-file threshold is supplied |
| L11 | [W3C ARIA25](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA25) | Informative sufficient technique, not required markup. Progressbar role is not a live region; status may be conveyed politely without focus movement. No requirement to announce every 500 ms/1%. Coarse speech cadence and truthful indeterminate status are project proposals |
| L12 | [MDN memory measurement](https://developer.mozilla.org/en-US/docs/Web/API/Performance/measureUserAgentSpecificMemory) | Limited, experimental availability; secure and cross-origin-isolated context required. Results differ by browser/version; sampling/available breakdown does not certify a portable peak worker/RSS ceiling. No 500 MB guarantee |
| L13 | [MDN crossOriginIsolated](https://developer.mozilla.org/en-US/docs/Web/API/Window/crossOriginIsolated) | COOP same-origin plus COEP require-corp/credentialless and permissions affect isolation and embedding/opener relationships. Headers are not a free instrumentation toggle or authorized hosting change |
| L14 | [MDN HTTP caching](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching) | Freshness/validation/content-addressed resources support repeat use; freshness duration is not guaranteed cache retention or offline availability. The 30-day target is a project choice |
| L15 | [MDN using service workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers) | Lifecycle and explicit cache strategy matter to offline reload. An already-loaded page working after network denial does not prove reload/persistence. No service worker installation/registration was performed |
| L16 | [Chrome device mode](https://developer.chrome.com/docs/devtools/device-mode/) | Emulation is an approximation; desktop hardware cannot reproduce all mobile architecture/behavior. Requires real-device evidence for the candidate support cells |
| L17 | [Chrome throttling](https://developer.chrome.com/docs/devtools/settings/throttling/) and [performance reference](https://developer.chrome.com/docs/devtools/performance/reference) | Supports explicit custom network rates and CPU settings/traces, and separates local/field metrics. Fixed 4×/1,600/750/150 numbers are proposed reproducibility inputs, not standard device equivalence |
| L18 | [MDN supportedEntryTypes](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceObserver/supportedEntryTypes_static) | Supported observer entry types vary by browser and context; feature detection is necessary. Availability alone is not collection completeness. Fallback trace equivalence, precision checks and unmeasured-cell handling are project protocol proposals, not a guarantee supplied by this API |

## Disposition of supplied research suggestions

| Suggestion / error | Draft disposition |
| --- | --- |
| Treat 2.5 s LCP as interactive time | Corrected: separate visible-content LCP and instrumented controls-ready timing |
| INP p75 as lab proof or standards-mandated 200 ms controls | Corrected: field guidance vs proposed per-interaction lab ceiling; no WCAG numeric latency claim |
|250 MB input / 500 MB memory / 50 MB catalogue / 20,000 entries | Unsupported as capacity promises; replaced by small explicit candidate envelopes, still baseline-dependent |
| Worker offload asserted as existing requirement/fact | Recast as proposed architecture; current synchronous buffer APIs and implementation gaps explicit |
| Cancel within 1 s **or next chunk** | Next-chunk escape rejected; foreground absolute deadline with host termination/invalidation design |
| Progress every 500ms/1%, speech at every update | Replaced with real or indeterminate phase status, separate UI heartbeat and restrained polite announcements; no fake percentage/ETA |
| Offline after load conflated with reload/persistence | Split; reload/cache policy needs separate WEB.2/storage review and permission |
| Memory API treated as universal worker peak instrument | Corrected support/isolation/measurement limitations and unknown≠pass; no production COOP/COEP change |
| Broad evergreen desktop and mobile support | Replaced by two physical candidate cells, one supplementary diagnostic cell and explicit exploratory browsers |
| “No record found” treated as exhaustive absence / budgets hereby adopted | Corrected to bounded recorded-evidence acknowledgement and PROPOSED prospective amendment; gate/holds unchanged |
