# Go carrier feasibility and experiment plan

Research proposal, 2026-11-18. Recommend a paired, synthetic experiment in **local binding order** and **local identifier choice**. Both modify recoverable source syntax; both have inexpensive normalization attacks. Neither is a robust carrier recommendation yet. No carrier size, payload length, redundancy scheme or detection threshold is selected. Fingerprints remain comparison/discovery baselines. Public algorithms and offline, private verification are requirements.

Read with [carrier feasibility](../02-carrier-feasibility.md), [evaluation review](../03-detection-evaluation-initial-review.md), [architecture comparison](../05-universal-signal-architecture-comparison.md), [code profile](../../profiles/code.md) and [roadmap](../../ROADMAP.md). This plan changes no normative contract. No private pilot was inspected or changed.

## Boundary and safety contract

First experiment: hand-authored synthetic, non-generated, non-vendor `.go` source in a standard-library-only module, Go language version 1.27, pinned compiler/formatter `go1.27.3`, initially `darwin/arm64`, `CGO_ENABLED=0`. Record module language directive, complete toolchain version, GOOS/GOARCH, tags, GOEXPERIMENT, selected files and source digests. Other configurations require separate checking; capacity is configuration-specific, never summed across mutually exclusive files.

Mark the selected source before compilation; recover from source. Binary/object survival, identical machine code, debug information, line locations, coverage layout, timing, scheduling, allocations and resource identity are outside this contract. Compiler optimization may erase syntax distinctions; a successful source result gives no executable detection claim. Files that read their own source, source-sensitive generators and instrumentation contracts are excluded.

Conservative whole-function grammar for the first comparison: an ordinary top-level function, no receiver/type parameters/parameters/named results; body consists only of a contiguous run of single-name `x := N` declarations followed by `return [n]int{x1,...,xn}`. `N` is a nonnegative decimal integer literal within signed 32-bit range; every local is returned exactly once. The array element order identifies each binding's role independently of declaration position and spelling. Names must be distinct lower-case ASCII identifiers. No nested blocks, comments in the body, explicit conversions or additional expressions. This intentionally tiny subset establishes an executable method; it estimates no application capacity. Do not add dead bindings or change return values to manufacture capacity.

Use complete-package parsing and `go/types` checking, with `Info.Defs`, `Uses`, `Scopes` and `Types` populated. Identify locals by resolved `*types.Var` objects, never matching identifier text. For renaming, edit the definition and every use of that object, then re-check and compare the binding graph modulo the intended bijection. Check candidate spellings against **every identifier in the function and file**, imports, package/universe names and reserved words; reject collisions/capture. Do not compare object pointer identities across separate type-check runs. These APIs resolve bindings/types; they are not effect or alias analyses. [Go types, go1.27.3](https://pkg.go.dev/go/types@go1.27.3#Info).

The proposed semantic argument is limited: literal initialization has no user calls or shared accesses; distinct fresh scalar objects are unaliased; return roles and values stay fixed. Alpha-renaming preserves each binding relation. Scope/capture and short-declaration rules still need checking. Go specifies evaluation ordering for calls and communication and has partially unspecified operand ordering; different destination names alone do not justify moving expressions. Package initialization is a separate mechanism. [Go specification, language go1.27, scope](https://go.dev/ref/spec#Declarations_and_scope), [short declarations](https://go.dev/ref/spec#Short_variable_declarations), [evaluation](https://go.dev/ref/spec#Order_of_evaluation), [initialization](https://go.dev/ref/spec#Package_initialization).

Explicit exclusions: assignments after initialization; addresses/pointers; slices/maps/interfaces; closures/captures; mutable aliases; user-defined/type-alias types; calls including builtins; indexing/dereferences; possible panics; division; floating point; I/O/global state; `defer`, `go`, channels, atomics, locks, `select`, loops and labels. Type aliases need resolution rather than spelling-based assumptions in any later expansion. Pointer aliasing and effects remain unsupported. Race-detector success would not prove schedule equivalence; synchronization is part of Go's memory model. [Memory model, June 6, 2022](https://go.dev/ref/mem).

Never rename exported/API objects, package declarations, functions/methods, fields, interface members, parameters/results, import aliases or package-level names, even unexported ones. Never change struct tags, strings or external ABI names. Exclude packages containing cgo, assembly, `unsafe` or compiler/linker directives from the first experiment; preserve all headers/directives byte-for-byte. Cgo's comment preamble is compiler input, and `go:linkname` can alias object symbols: comments and unexported names cannot be treated uniformly as inert. [cgo docs, go1.27.4](https://pkg.go.dev/cmd/cgo), [compiler directives, go1.27.4](https://pkg.go.dev/cmd/compile#hdr-Compiler_Directives).

Build constraints and platform filename suffixes select files; release tags can affect file language versions. Preserve `//go:build` and legacy constraints and report excluded files. Initially reject tagged/platform-specific files rather than silently claiming all-build coverage. [go command, go1.27.3](https://pkg.go.dev/cmd/go@go1.27.3#hdr-Build_constraints). Reject files with `//go:embed` and never modify matching assets: the directive binds compile-time file contents to a variable and its placement matters. Later support needs selected-asset digests and a configuration matrix. [embed docs, go1.27.4](https://pkg.go.dev/embed#hdr-Directives).

Passing compilation/tests is bounded validation. The restricted semantic argument must stand separately; broadening the grammar needs a new argument and counterexample suite.

## Candidate comparison and raw capacity

| Family | Source change and extraction | Raw states before redundancy | Expected weakness to test |
| --- | --- | --- | --- |
| A: local binding order | Permute the eligible run. Order bindings by their unchanged return-array role to define a canonical list; lexicographic permutation rank recovers a symbol. | For a fully independent run of n bindings: n! states; fixed binary capacity floor(log2(n!)). Report n and states for every run. | Sorting by return role erases distinctions without knowing the key. Splitting/moving declarations breaks alignment. |
| B: local identifier choice | Give each eligible object one of m prevalidated spellings in a published, role-specific disjoint codebook; update all resolved uses. Extract spellings in return-role order. | Product of actual permitted spelling counts m_i; floor(log2(product m_i)) for joint coding. If coding each site independently, sum floor(log2(m_i)); do not interchange these. | Canonical alpha-renaming erases the channel. Naming conventions and readability sharply constrain choices. |

Enumeration order, accepted ranks and any unused states must be public and deterministic. Four bindings giving 24 order states and four fixed bits is illustrative accounting, not a chosen group/payload size. For B, existing original spellings may be outside the codebook; count required edits and quality refusals. Ensure a claimed embedding changes bytes: an already-matching assignment is `already_matching/no_change`, not a newly embedded success.

Report raw capacity per function/file and capacity distribution including zeros. Independence must be established before multiplying state counts; overlapping carriers share constraints. Do not add A and B capacities without a joint state test. Net payload capacity subtracts synchronization, identity/context authentication, framing, error correction and repetition; until those are specified, report it as unknown. A group too small for a requested encoding is `unmarkable/insufficient_capacity`; preserve original bytes. Also retain parse/type/config/eligibility failures and post-edit validation failures, with reasons. Never fall back silently to a fingerprint or a broader rewrite.

## Recovery, keys and references

First mode is expected-identity, reference-assisted verification: local verifier receives candidate source, original synthetic reference, profile/config, expected identity, test-only key and embedding nonce. Keep key/nonce outside marked source; publish benchmark keys for reproducibility, never production secrets. A public deterministic keyed schedule can map identity and a canonical region digest to carrier choices; an actual construction and domain separation must be frozen before implementation. A MAC/identity check costs capacity and does not prevent replay of an intact marked region. Public algorithm does not imply public access to private verification keys.

Canonical region representation strips the chosen spellings and declaration order while retaining literal values, return roles and syntax. It avoids a final-digest/key derivation cycle, but independent equivalent regions can share it: test that ambiguity explicitly. Record original and final exact digests separately. Reference matching supplies an alignment hypothesis, not a proof of ancestry. Initially fail/abstain on ambiguous alignment; do not silently fill missing carrier symbols from the reference.

Recover symbols, expected identity match/mismatch, integrity result and localized evidence separately. Report candidate UTF-8 byte intervals `[start,end)` and corresponding reference intervals, artifact digests, build configuration and surviving/missing/changed sites. File-only fragments lacking package context may be unsupported; a synthetic wrapper must be recorded and cannot count as original context. Blind discovery over many references/keys is a later, separately calibrated search, not an extension of an expected-key error rate.

## Tests and shared measurement contract

Use the same held-out fixtures for A, B, fingerprint-only and a frozen combined rule. Measure original/final fingerprint drift. Split by synthetic program family before tuning; do not count permutations of one program as independent repositories. No ownership or rights inference follows from recovery.

| Test | Required observation |
| --- | --- |
| Clean round trip | Every accepted carrier state extracts exactly; wrong key and wrong expected identity are separate negative queries. Verify identity, symbol errors and abstentions. |
| Negatives | Unmarked originals, independently authored same-task functions, common literal-return templates and different identities. Include naturally matching carrier states. |
| Ordinary tools | Pinned `gofmt`, `gofmt -s`, parse/print cycle, comment/header preservation, unrelated file/import edits and function relocation. Record exact versions and bytes; do not infer future formatter stability. |
| Removal | Sort A by return role; alpha-rename B by return role; combine both; rewrite locals into direct return constants; inline/extract supported expressions. Measure attack cost and refused/invalid rewrites. |
| Partial copy | Copy whole function, complete run, truncated run, and fragments crossing group boundaries into synthetic hosts. Report surviving symbols and supported scope, not just whole-file success. |
| Transplant | Transfer only order/spelling choices onto independent same-task code; transfer onto changed constants; copy the intact marked function into an unrelated host; mix regions from identities. Distinguish signal replay, actual copied source and wrong host-wide attribution. |

An attack is valid only under a declared behavior contract: type-check/build plus expected return values for this finite fixture, and a rule-level semantic justification. Record invalid attacks separately from valid evasions; compilation alone is insufficient. A direct-return rewrite can validly remove all carriers here. Whole marked-function copying may recover the function identity; report that local scope rather than claiming its host is marked. Transplant context binding cannot rule out copies sharing the same canonical representation.

Freeze the following units/denominators in a local experiment manifest (no schema change):

- Eligibility = eligible functions / all enumerated functions, plus files/configurations skipped. Embedding completion = changed and validated embeddings / requested embeddings; include zero-capacity and tool failures.
- Clean/attacked exact recovery = correct complete identity recoveries / embedded cases (conditional), and / all requested cases (end-to-end). Also report symbol errors / extracted expected symbol positions, erasures separately, and exact identity errors / completed decisions. These are different units.
- False alerts = negative **full catalogue searches** producing at least one merged alert / negative full searches, with actual key/reference/window counts. Report wrong-key and wrong-identity counts separately. Pairwise/site error rates cannot stand in for search error rates; correlated synthetic variants give no rare-event guarantee.
- Valid attack rate = valid outputs / attempted attacks; evasion = valid attacks causing missed/wrong recovery / valid attacks. Retain attack execution failures and invalid transformations.
- Localization = matched byte overlap/precision and recall against known copied intervals, plus recovered identity scope, copied bytes/tokens and surviving sites. Partial-copy recall denominator includes unsupported fragments, with a separate conditional result.
- Runtime/memory = enumeration, type checking, embedding, extraction, search and each attack separately; report wall time, peak memory, input bytes, function/site counts, hardware, repetitions and timeout/error counts. No runtime budget or accuracy promise is inferred from a smoke test.

Formatting is versioned behavior: Go's formatter documentation explicitly recommends pinning `gofmt` when stable output matters. [go/format, go1.27.3](https://pkg.go.dev/go/format@go1.27.3).

## Next smallest executable experiment

Parent can authorize a separate implementation change: a standard-library-only harness over generated synthetic instances of the grammar above. Enumerate small n values and explicit spelling alphabets as **test dimensions**, report all state counts, and round-trip both families independently. Include refusal fixtures for shadowing/capture, mixed `:=` redeclaration, aliased mutable data, side-effecting RHS, goroutine/closure capture, tags, cgo, embed, exported/field names and malformed input. Require deterministic refusal and unchanged bytes.

Start with exact expected-symbol recovery, clean/wrong-key/wrong-identity/unmarked controls, formatter survival, the two canonicalizers and direct-return removal. Add one whole-function copy and one signal-only transplant before selecting payload size or error correction. Exit gate: reproducible counts/bytes, every failure retained, safety reasoning reviewed, and attack validity separated from detector outcomes. Stop for redesign if clean extraction or semantic gates fail. Synthetic success only justifies a later authorized public-corpus eligibility census.

Actual validation in this lane: reran existing [Go carrier checks](../experiments/go-carrier/carrier_test.go) with `go test -v -count=1 ./...` from its module on `go1.27.3 darwin/arm64`. Both tests passed: 24/24 literal permutations retained output and order through `go/format`; sorting collapsed 24 orders to one; the side-effecting-call counterexample changed effect order. Go reported package time 0.932 s (not a detector benchmark). No identifier-carrier, eligibility analyzer, keyed extractor, attack detector, corpus census or compiled-artifact experiment was executed. Primary references were checked on 2026-11-18; specification language version is go1.27, package docs are versioned as linked above. Remaining blockers: realistic eligible capacity, a reviewed binding-preserving transformer, a concrete context/key/framing protocol, fragment synchronization and calibrated full-search errors.

Repository checks attempted: `python3 tools/validate.py` and `python3 -m unittest discover -s tests -v` both stopped at import because the available Python environment lacks `jsonschema`; neither is recorded as passing. No dependencies were installed in this shared checkout.

## Self-contained external deep-research prompt

> Research two post-hoc embedded source-mark families for Go: permutation of independent local literal bindings and scope-aware local identifier choice. Source must actually change and support later recovery. Fingerprints are comparison/discovery baselines. Public algorithms and offline private verification are mandatory. No carrier/payload size is selected. Use public primary references, versioned Go specification/compiler/type-checker/tool docs and synthetic examples; do not access private applications or paid services. Produce a concise feasibility comparison and smallest executable experiment, not a production embedder or normative schema.
>
> Begin with ordinary non-generic parameterless functions containing only distinct single-name `x := N` declarations (nonnegative decimal literals fitting signed 32 bits) and a fixed `[n]int` return listing each object once. Explain a semantic argument separate from passing tests. Specify go/types Defs/Uses/Scopes binding resolution and post-edit graph checks; exclusions for capture, short redeclarations, aliases, effects, evaluation order, panic, concurrency, exported/API/field names and source-sensitive behavior. Address build tags/platform filenames, module/file language versions, cgo preambles, go:embed assets, compiler directives, formatting and source versus executable artifacts. Identify safe expansions only with explicit proof obligations and counterexamples.
>
> For each family define eligibility/refusal behavior, raw state capacity before framing/redundancy, extraction/key/reference assumptions, local byte localization, synchronization and partial-copy limits. Compare clean recovery, ordinary tools, canonicalization/removal, direct-return rewriting, fragments, mixed identities and signal-only/intact-fragment transplants. A key or context digest is no ownership proof and cannot prevent intact-region replay. Avoid guarantees of robustness or false positives.
>
> Use shared metrics: eligibility and embedding failures; correct identity recovery conditional on completed embedding and end-to-end over all requests; wrong key/identity, unmarked and independent same-task controls; symbol error/erasure units; full-catalogue-search false alerts with explicit counts/dependence; valid attacks divided by attempts and evasion divided by valid attacks; byte localization/partial-copy scope; runtime/memory and failures. Compare mark-only, fingerprint-only and a calibrated combined rule on the same held-out program families. State what was actually executed, versions/commands/results, versus proposed. Cite exact primary URLs and distinguish language guarantees, implementation observations and hypotheses. End with blockers and the next smallest experiment; select no payload length without measured capacity.
