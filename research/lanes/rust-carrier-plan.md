# Rust carrier feasibility and experiment plan

Status: research proposal, 2026-11-18. Scope: synthetic Rust source, local/private verification, public algorithms. No carrier block size or identity/payload length is selected. This plan follows ROADMAP M2E and the code profile; fingerprints remain comparison baselines. No private pilot was inspected. No embedder, detector or new Rust experiment was executed in this lane.

Recommend comparing **integer-literal spelling** with **independent local-declaration order**, starting with spelling because its value-preservation argument is smaller. Both change source bytes and permit later source extraction; both admit cheap canonicalization attacks. Neither currently supports a robustness claim. Existing two-order Rust checks in `research/02-carrier-feasibility.md` are prior evidence, not this lane's results.

## Boundary and eligible subset

First experiment: hand-authored, dependency-free synthetic crates, edition 2021, pinned compiler/formatter, explicit target and flags, no build script or procedural macros. Input/output are UTF-8 `.rs` bytes **before expansion**. Detect from retained source, never by executing suspect source. Compiled objects, executables, MIR, expanded source and debug information are separate unsupported artifact profiles; optimization may eliminate the distinctions. No binary-equivalence promise follows from source equivalence.

Use only private, non-generic, synchronous free functions with zero parameters and a body consisting of consecutive immutable bindings followed by an array expression containing every bound name exactly once in a fixed order. Each binding has exactly the form `let name: u32 = literal;`, with a fresh ASCII identifier, no shadowing, attributes, comments or destructuring. The literal has an explicit `u32` suffix and an in-range nonnegative value. No other expressions or nested items occur. Resolve `u32` as the primitive type; reject a scope that shadows it. This tiny subset is an experiment grammar, not a proposed useful production coverage level. Preserve function names, visibility, signatures and all API/ABI names; private names can still be observed by tooling or macros, so privacy alone is insufficient.

| Family | Source choice and raw states | Safety argument inside the subset | Expected failure pressure |
| --- | --- | --- | --- |
| Literal spelling | At each existing literal with at least two decimal digits: canonical decimal digits plus `u32`, or the same digits with one underscore immediately before the last digit, e.g. `1234u32` / `123_4u32`. Exactly two allowed states per site. | Same suffix, primitive type and in-range value; Rust removes integer-literal underscores when computing the value [R1]. No inference or arithmetic changes. | Removing digit separators erases this channel. Formatter behavior must be measured, not assumed. |
| Declaration order | Permute a complete contiguous run of the eligible bindings; retain each name/value pair and the final array order. | Literal initialization has no call, borrow, allocation or user destructor; no binding reads another. The final array reads the same primitive values. | Sorting bindings by unchanged name erases the channel. Rename/refactor may disrupt alignment. |

Ownership/borrowing rules matter even when transformed code compiles. This subset introduces no reference, borrow, lifetime parameter, move of a non-`Copy` resource, temporary guard or capture. Generalization to references or owned values is blocked pending a separate argument: local drops occur in reverse declaration order [R2], so moving two guards can alter observable effects. Do not reorder merely because dependency analysis or borrow checking succeeds. Do not change lifetime syntax, scope boundaries, shadowing, pattern binding modes or temporary lifetimes.

Exclude calls/methods, mutation, shared state, I/O, atomics, locks, allocations, panics, indexing, arithmetic, casts, control flow, async/closures, `const` contexts, trait/generic code, overloaded operators, custom `Drop`, `unsafe` functions/blocks, FFI and raw pointers. Operator spelling is insufficient to establish purity because traits can overload operators [R3]. Do not insert dead code, telemetry or new literals to manufacture capacity. Runtime values and specified effects must remain equal under the subset argument; compiler success and passing tests provide only bounded checks. Debug stepping, source spans, diagnostics/lint output, compile time, binary bytes, execution timing, stack layout and source-text introspection are outside the equivalence claim. If any are required behavior, declare the input unmarkable under this profile.

Reject macro definitions/invocations and expansions, `include!`/`include_str!`, generated/vendor code, attribute/derive macro targets and source-reading build steps. Declarative macros can distinguish tokens and have mixed-site hygiene [R4]; proc macros consume tokens, are unhygienic and can access files [R5]. Consequently, excluding only the edited token from a macro call is insufficient: a proc macro elsewhere or build script can read the file. Initial crates exclude those facilities entirely. Future census needs an explicit audited source-observer boundary, not an AST-only safety claim.

Reject `cfg`/`cfg_attr`, feature-gated enclosing modules and custom configuration in the initial grammar. Conditional compilation depends on target and compiler inputs [R6]; one passing feature combination says nothing about another. Future extensions must record and validate each supported target/features/profile combination, report excluded combinations, and never silently mark inactive branches as validated. API renaming and macro hygiene transformations are outside both families [R4,R5,R7].

## Capacity and extraction assumptions

Report candidates, eligible functions/runs/sites, rejection reasons and raw state count **before** redundancy. For a run of n distinguishable bindings, order has n! states and at most `floor(log2(n!))` fixed-length bits. For m disjoint spelling sites it has 2^m states and m raw bits. If combining channels, avoid double counting overlapping scheduling/context choices; an independence argument is required before multiplying states. Counts describe available encodings, not entropy of natural code or error probabilities. Formatting, quality constraints and reserved states may reduce capacity. Synchronization, context binding, authentication, identity, repetition and error correction must each be debited before choosing a payload. No useful capacity on real code is known.

Initially specify a **reference-assisted, expected-identity** decoder: local access to candidate source, original and marked references, eligibility manifest, frozen profile/config, and a test key/seed. Extraction reads actual candidate token spelling/order; a reference digest or fingerprint match alone cannot recover an embedded mark. Align complete functions using recorded structural context; ambiguous, duplicate or missing anchors produce erasures/abstention. Record UTF-8 byte intervals `[start,end)` against candidate digests. For order, rank binding permutations against a canonical ordering of the unchanged names; for spelling, read only the two permitted variants. Unexpected forms are erasures, not implicit zeroes.

Make the state mapping, ordering, serialization, alignment and rejection rules public. Keep any production key and reference catalogue local. Synthetic reproducibility uses disclosed test-only keys/seeds. Before implementation freeze a domain-separated standard keyed construction and exact inputs for identity/context binding; do not derive a secret from public hashes alone. Raw extraction can be tested before identity authentication exists, but must not be reported as verified identity recovery. Wrong key, wrong expected identity and changed context must be distinct controls. Blind multi-key discovery requires a later separately calibrated search protocol. Signatures/trust remain independent of tolerant mark detection.

If parsing, eligibility, capacity, alignment or quality gates fail, return `unmarkable` with reason and unchanged original bytes/digest. Never emit a partial successful mark silently; record attempted and completed sites and any rollback. No detection means `not_detected` under the named configuration, not proof that a mark never existed.

## Smallest next executable experiment

Implement a dependency-free synthetic fixture generator plus reference-assisted raw-state extractor in a later change. Enumerate all permutations for several small run lengths and both spellings at independently varied sites; these are test dimensions, not selected carrier sizes. Start with clean state round trips, deterministic reruns and rejection fixtures. Include guards with observable `Drop`, a borrow/dependency, shadowing, an effectful initializer, a token-sensitive macro, an attribute macro and conditional branches as **rejection** fixtures. Counterexamples should demonstrate why excluded transformations are unsafe, without proposing them as valid attacks.

Then apply the same recorded matrix independently and in combinations:

| Test class | Concrete operations and controls |
| --- | --- |
| Ordinary tools | Pinned `rustfmt` defaults and declared project config; repeated formatting; debug/release compilation and tests; lint-only checks, then pinned automatic lint fixes as a separate transformation. Record which operations actually change source. Do not treat a build that preserves the source file as evidence of binary recovery. |
| Deliberate removal | Strip separators; sort eligible runs by name; normalize both; consistently rename locals; inline/remove bindings or rewrite the function while preserving outputs. Use public-algorithm attackers with and without key/reference access, fixed effort budgets and logged failures. |
| Fragments | Whole function; contiguous excerpt with full/partial run; cut through a literal; split/move/duplicate runs; mix marked and unmarked functions in a larger host. Report surviving complete sites, erasures, alignment errors and recovered scope. Tiny fragments may have zero decodable capacity. |
| Transplant/forgery | Copy a marked function into an unrelated host (real marked-fragment copy); separately impose only its spelling/order pattern on an independently written same-task function (signal-only transplant). Test changed context/identity, copied references and duplicate anchors. Context binding may reject some transplants while reducing partial-copy recovery; measure both. |
| Negatives | Original unmarked inputs, independently written same-task programs, common templates, other identities, wrong keys and unrelated repositories. An unmarked source can naturally occupy a valid raw state; state decoding alone is not a positive identity decision. |

For each attack report compilation/fixture-output validity separately from evasion, including invalid/unsupported/timeout counts. A semantics-preserving claim needs the restricted argument above or a separate proof; finite tests cannot certify arbitrary rewrites. Report changed source size, transformation cost and detectability tradeoffs without predicting survival.

Use the shared Go/Rust conceptual metrics: eligibility = eligible/input functions; embedding success = completed/attempted eligible inputs; clean exact recovery = complete correct record/successfully marked inputs, plus end-to-end recovery over all requested inputs. Until an identity protocol exists, label raw-state recovery separately and identity recovery unavailable. Report bit/symbol errors and erasures with their transmitted-unit denominators. Attack validity = valid/attempted transformations; conditional evasion = nonrecoveries/valid attacked marked inputs, with end-to-end counts over all attack attempts. Report wrong-identity acceptances and abstentions explicitly.

False alerts use the **full repository query** as primary unit: queries with at least one incorrect accepted identity divided by negative repository queries under a fixed catalogue/key count and merging rule. Also retain per-comparison counts; do not substitute them for query errors. Group related fixtures/versions in the same split; tune only on calibration data, then freeze thresholds. Tiny synthetic negatives establish no rare-event bound. Localization precision/recall uses byte intervals against known copied regions; partial-copy recovery is stratified by copied bytes, complete sites and fraction of original carrier, without extrapolating identity to the host repository. Record wall time and peak memory separately for eligibility, embedding, extraction, reference search and validation, including hardware/tool versions and failures. Compare mark-only, fingerprint-only and a frozen combined rule on the same cases/error unit; fingerprint identity recovery is not applicable. No score establishes ownership, permission or ancestry.

This plan fixes edition 2021; it does not claim coverage of subsequent language changes.

Blockers to adoption: unknown useful-code eligibility/capacity, unimplemented reference alignment and identity protocol, unmeasured formatter/refactor survival, trivial normalization and transplant risk.
