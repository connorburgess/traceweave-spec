# Review of the supplied specification

Reviewed against the user-supplied Stemma draft, sections 1–10. Traceweave is the chosen project name. The original attachment is retained locally as review input, not promoted to a normative 1.0 release. This review is a design assessment, not a full cryptographic audit.

## Blocking findings

1. **Private-by-default conflicts with required public signing and resolution (§§2.4, 3, 8).** Mandatory Rekor publication, full returned feature vectors, and in-repository key storage can expose participation and private evidence. Make public disclosure optional, keep catalogues outside the source tree, and defer network resolution until its leakage model is specified.
2. **Prefix bucketing is not a demonstrated k-anonymity guarantee (§3.2).** A 16–24-bit prefix does not guarantee a minimum anonymity set. Multiple prefixes, rare features and adaptive queries can identify a target. Shared-key HMAC does not make this zero knowledge; authorized consortium participants can compute dictionary candidates. Remove the guarantee and benchmark leakage before proposing a resolver.
3. **The false-positive formula and numerical guarantees are unsupported (§6).** Normalized token dependencies, same-spec code, multiple comparisons and corpus selection invalidate the proposed independent-token shortcut. The rule of three is conditional on sampling assumptions, not a license to tune against 300,000 files and declare a universal bound. Replace with held-out whole-pipeline evaluation.
4. **Wire formats are not interoperable as written (§2).** The in-toto v1 type is `https://in-toto.io/Statement/v1`, not the draft URN. DSSE PAE requires explicit space separators and decimal byte lengths. An RFC 3161 token is signed verification material, not an ISO date string. See [in-toto](https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md), [DSSE](https://github.com/dsse-lf/dsse/blob/master/protocol.md), and [RFC 3161](https://www.rfc-editor.org/rfc/rfc3161).
5. **Signatures are used to overstate ancestry and replay resistance (§5).** An attacker can sign copied public material or transplant marked fragments. A valid signature authenticates the statement under a trust policy; it does not establish authorship. Preserve exact verification, similarity evidence and rights review as separate results.
6. **Commit cutoffs overstate rights (§7).** Older permissive expression can persist after the transition, and permissive redistribution has conditions. Post-transition code is not automatically proprietary original expression. A permitted copy is still a technical reuse match. Use region-level histories and actual licenses. [Apache 2.0](https://www.apache.org/licenses/LICENSE-2.0).

## Major technical findings

- **Winnowing is conflated with MinHash (§4.1).** The profile switches between rolling hashes and BLAKE3 without specifying the conversion. Tie-breaking, hash encodings, grammar versions, scope normalization and parser failure behavior are missing. Whole-file Jaccard hides extracted fragments in large hosts. Require a deterministic profile and local containment/alignment.
- **Unvalidated robustness labels (§§1, 5).** Passive fingerprints do not generically survive refactoring or compression. Whitespace can be syntactic, and docstrings are not always comments. Exact AST hashes do not survive arbitrary loop inversion. Remove “100%,” categorical survival, and mathematical-impossibility claims without explicit assumptions and evaluations.
- **Modality descriptions need correction (§4).** The image recipe excludes the DC coefficient from 64 coefficients but still calls the result 64 bits. Chromaprint is conflated with a peak-constellation design and assigned an unsupported universal BER. TLSH digest size/encoding and hard distance thresholds need a versioned definition and empirical support. Treat each as a separate research profile. [Chromaprint](https://github.com/acoustid/chromaprint), [TLSH](https://github.com/trendmicro/tlsh).
- **Abstention rules conflict (§§5–6).** Thresholds of 20, 25/35, and 40 tokens serve different purposes without clear distinction. Requiring three independent subtrees can reject a distinctive single-function copy. Keep theoretical locality separate from empirical evidence sufficiency; calibrate rather than invent universal cutoffs.
- **Sigstore requirements are overstated (§2.4).** The bundle format does not mandate all of keyless signing, transparency, and RFC 3161 together. Fulcio certifies a supplied public key; it does not supply the client's private key. Time evidence does not guarantee indefinite archival validity. [Bundle documentation](https://docs.sigstore.dev/about/bundle/).
- **Schema gaps (§10).** Use the real JSON Schema 2020-12 dialect URI, reject unexpected fields where appropriate, constrain digest lengths and nonempty arrays, distinguish draft versions, and use real test fixtures rather than ellipsis placeholders. The example's supposed 64-bit values have only eight hex digits. Shape checks still cannot validate signatures or rights.
- **A single verification cost is misleading (§1).** Hashing and parsing the signed message depend on its size; trust-chain and timestamp validation add work. A detached signature can still verify when a derivative changes, while the derivative's exact subject digest fails.

## Recommended disposition

Keep the layered concept: shared evidence records, exact digests, optional standard signing, content-specific fingerprint profiles, and explicit abstention. Replace the supplied 1.0 draft with a small 0.1 design scaffold. Start locally with a code baseline; leave a resolver, broader modality algorithms, production skill, and claims of transformation resilience gated on evidence.
