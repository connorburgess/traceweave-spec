## Evidence scope and implementations

Go and Rust refer to the independent implementations in `connorburgess/traceweave`, not the Python fixture checkers here. Recorded core evidence is the [core review](../../research/reviews/core-gates-m1-m2-review.md) and [implementation review](../../research/reviews/implementation-merge-i2-review.md). Later implementation review paths and pins are recorded in [ROADMAP.md](../../ROADMAP.md): TS/TXT `8011b6d`, PY `b5d981c`, WASM `51f29d7`, registration `5b9a881` with spec pin `9cf78ee`. These are evidence snapshots, not claims about a newly fetched latest build. No held evaluation was run for this document. Implementation evidence below is pinned and distinguishes complete fixture suites from sampled WASM checks.

**Recorded** means the cited repository record reports passing the stated applicable fixtures, not every related API or adapter. **Sampled** means only the specifically enumerated parity cases were tested. **Draft** means specified/research only. **Unverified** means this repository has no sufficient conformance evidence. Shelf static app is an explicitly listed implementation target; no independent complete conformance run is supplied here, so every capability is unverified; this does not assert those capabilities are absent. The implementation review `docs/reviews/web-wasm-review.md` at `51f29d7` records 451 extraction, 76 record, 214 catalogue and 93 matching-body cases, but only 5 reference cases and 4 registration verify/render cases. The latter include bundle-three-roots, bundle-real with local RFC 3161/OTS material, and simulated-rendering refusal. Its additional adversarial opening checks are not a complete changed-opening or report-link/key-event suite. Browser WASM parity establishes those tested core function bytes; it does not establish all Shelf UI flows or native filesystem/build behavior.

## Migration and compatibility rules

1. **Pin the whole contract.** Record the specification commit, applicable `spec/`, `profiles/`, `schemas/` and vectors, implementation commit and supported conformance levels. Preserve exact configuration bytes, `configSha256`, profile versions, input bytes/digests and canonical output fixtures. Fixture checker success alone is not a production verifier claim.
2. **No silent reinterpretation.** A change to tokenization, Unicode tables, folding, hash framing, channels, offsets, canonical serialization or matching semantics that changes any frozen output needs a new contract/profile version and configuration digest. Keep old vectors to test old behavior; never recalculate old expected bytes to disguise an incompatible algorithm change. Unknown profile/version combinations are rejected. TypeScript draft-1 outputs are superseded: select `ts-tokens/draft-2` and its new exact config digest, never reinterpret draft-1 bytes. TSX and Markdown drafts remain separate from frozen Stage 1.
3. **Promoted paths.** The [promotion map](../../research/promotion-map.md) records draft-to-`spec/`, `profiles/`, `schemas/` and `test-vectors/` moves. A path-only move is not a wire migration. Canonical schemas live in `schemas/`; do not keep a second divergent copy under matching vectors. JSON Schema checks structure; the checkers enforce byte framing, ordering, digest binding and semantic rules.
4. **Minimal core versus registration.** The minimal `0.1.0-draft.1` commitment predicate and registration-draft-5 are distinct adapter forms, not interchangeable schemas. Select by exact payload type/predicate/version and preserve signed decoded bytes. Do not rewrite an old signed payload to upgrade it; create a new signed record under the new version and retain the old one. Regenerate `tw1-` references and report links when the bound statement/report bytes change.
5. **Private retained material.** Copy catalogue bytes verbatim, not through a JSON serializer; retain private nonces and local time/trust evidence outside source trees. A reserialized catalogue can have equivalent JSON yet fail the original commitment. Do not import test fixture keys/roots into production trust. Public disclosure, live timestamp submission and hosted resolution are separate actions.
6. **Revalidate on upgrade.** Run `tools/validate.py`, `--links-all`, unit tests and hygiene with pinned development dependencies, then reproduce the applicable positive and negative vectors in each implementation. Separately audit behavior outside output bytes (resource bounds, nonce APIs, side channels, diagnostics, native outputs, UI claims). Independent review for M5.1/M5.2/M5.4/M5.5 is recorded above; M5.3 still requires its independent offline demonstration.
